# Сценарии Vanessa в этом проекте

Сценарии — `features/`, один функционал на файл. Образец рабочего сценария —
`features/НовыйТовар.feature`: подключение, раздел, создание, ввод, выбор из списка,
запись, проверка строки списка. Новый сценарий начинать с него, а не с исследования
формы. Команды запуска, пути и профиль клиента — раздел «Под своё окружение».

## Порядок работы

1. Нет инструментов `vanessa` в сессии — сказать человеку и остановиться. К серверу по
   HTTP самому не обращаться: без харнесса каждая попытка — новая сессия
   и переподключение клиента.
2. `manage_test_client` с действием `connect` и профилем из раздела «Под своё окружение».
3. Сначала написать шаги в feature, затем `open_feature_file`, `check_syntax` и
   `run_scenario` с `reloadAndRun`: оба работают с файлом, открытым в редакторе Vanessa.
   Упавший шаг разбирать по форме (`get_form_analysis` с `only_visible` и `compact`,
   `get_form_element_data`). Ручные действия в форме — только чтобы узнать имя
   элемента или проверить один шаг, не вместо сценария.
4. Пути файлов в инструментах `vanessa` — полные пути, как их видит 1С.
5. Пробный сценарий для одного шага — в каталоге логов, не в `features/`.
6. Готово — только свежий пакетный прогон (раздел «Под своё окружение»): `status.txt`
   со значением 0 и JUnit без failures и errors. Success через MCP — ещё не готово.

## Шаги, которые работают

Имя шага не искать `search_for_steps_by_keywords`, если оно есть здесь или в образце.

| Нужно | Шаг |
|---|---|
| Подключиться к клиенту | в `Контекст`: `Дано я подключаю профиль TestClient "<профиль>"` — без него пакетный прогон берёт клиент менеджера |
| Открыть раздел | `И В командном интерфейсе я выбираю '<Раздел>' '<Команда>'`, затем `Тогда открылось окно '<Заголовок>'` |
| Уникальное значение | `И Я запоминаю значение выражения 'Формат(ТекущаяУниверсальнаяДатаВМиллисекундах(), "ЧГ=0")' в переменную "Метка"`, дальше `'$Метка$'` |
| Поле ввода | `И в поле с именем '<Имя>' я ввожу текст '<текст>'` |
| Ссылочное поле шапки | `И из выпадающего списка с именем '<Имя>' я выбираю по строке '<текст>'` |
| Ссылочная колонка таблицы | `И в таблице "<Таблица>" я нажимаю кнопку выбора у реквизита с именем '<Колонка>'`, в форме выбора `И в таблице "Список" я перехожу к строке:` с колонкой `'Наименование'`, затем `И я нажимаю на кнопку с именем 'ФормаВыбрать'` |
| Ввод в ячейку | `И в таблице "<Таблица>" в поле с именем '<Колонка>' я ввожу текст '<текст>'`, после каждого — `И в таблице "<Таблица>" я завершаю редактирование строки`: без него обработчики изменения не срабатывают |
| Проверить значение | `Тогда элемент формы с именем '<Имя>' стал равен '<значение>'`; в таблице — `И в таблице "<Таблица>" поле с именем '<Колонка>' имеет значение '<значение>'` |
| Запомнить значение | `И я запоминаю значение поля с именем '<Имя>' как "<Переменная>"` |
| Записать и закрыть | кнопка `ФормаЗаписатьИЗакрыть`, затем `И я жду закрытия окна '<Заголовок>*' в течение 20 секунд` |
| Код в базе менеджера | `И я выполняю код встроенного языка на сервере` — серверный контекст базы менеджера, клиент тестирования не нужен (проверено 24.11.2026) |
| Код в базе клиента | `И я выполняю код встроенного языка на сервере (Расширение)` — через `VAExtension` в базе клиента тестирования, требует подключения клиента; код исполняется в безопасном режиме |

Заголовок новой или изменённой формы кончается звёздочкой: `'... (создание)*'`.

## Грабли

- Ссылочное поле не перебирать построчно (`goto_first_row`, `navigate_next_row`) и не
  смотреть скриншотами: сразу шаг из таблицы выше. Значение — по переменной сценария,
  не первая строка списка.
- Панель функций раздела блокирует клиент, пока не выбрана команда. Раздел открывать
  шагом командного интерфейса, а не `click_section_panel`; открылась панель —
  `manage_command_interface` с `close_function_panel` один раз.
- После загрузки расширения в базу открытый клиент тестирования видит старое
  расширение: перезапустить клиент (раздел «Под своё окружение»), затем снова
  `connect`. Менеджер не перезапускать — сессия MCP у агента пропадёт.
- Менеджер, запущенный только с `runMcp`, отдает один инструмент `infobase_info`.
  Полный набор регистрирует сценарий `tools\reg-mcp.feature` (`Ванесса.МодульMCPVA()
  .ЗарегистрироватьИнструментыMCP()`), его выполняет стартовая команда менеджера
  (`StartFeaturePlayer;ЗагрузитьФичи;ВыполнитьСценарии;КаталогФич=...\reg-mcp.feature`);
  успех — строка `==MCP-OK== Инструменты MCP зарегистрированы` в `logs\manager.log`.
  Инструменты видны только сессии агента, начавшейся после регистрации.
- Шаг с кодом «на сервере (Расширение)» без подключенного клиента падает
  («Клиент тестирования не подключен») — подключить клиента шагом из `Контекста`
  или взять шаг «на сервере» без «(Расширение)».
- При падении шага Vanessa кладёт снимки рядом с feature; в git они не идут.
- Ожидаемое значение в сценарии — из требования. Форма показывает другое — это находка:
  сообщить, а не подгонять ожидание.

Перед загрузкой расширений и запуском менеджера закрыть клиенты 1С рабочей базы:
открытый сеанс мешает обновлению. В этом проекте сеансы в рабочей базе разрешено

**База-менеджер.** Менеджер тестирования живёт в отдельной пустой базе: в рабочей базе
её стартовые окна не дают открыться обработке. Создать один раз, загрузить в неё
`client_mcp` и снять с него безопасный режим и защиту от опасных действий — без этого
`client_mcp` не может открыть feature-файл и сделать снимок. Команды проверены на этой
машине 24.11.2026 на одноразовой базе: каждая завершается с кодом 0, менеджер в такой
базе поднимается и слушает свой порт MCP. В этом проекте база уже создана и подготовлена;
повторная загрузка `client_mcp` — только по команде человека:

```bat
"C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe" CREATEINFOBASE File="C:\vanessa\va-manager85"
"C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe" DESIGNER /F"C:\vanessa\va-manager85" /DisableStartupDialogs ^
  /LoadCfg "Q:\AIZCODE.DZ8\tools\client_mcp.cfe" -Extension client_mcp /UpdateDBCfg ^
  /Out "Q:\AIZCODE.DZ8\logs\client_mcp.log"
```

В установке 8.5.1.1529 `ibcmd` нет. Проверено 24.11.2026 серверным шагом «И я выполняю
код встроенного языка на сервере»: у обоих расширений базы-менеджера (`client_mcp` и
`VAExtension`) уже стоит `БезопасныйРежим=Нет` и `ПредупреждатьОбОпасныхДействиях=Нет`,
поэтому снимать флаги сейчас не нужно. Если база пересоздается, снять флаги в
Предприятии базы-менеджера: «Все функции → Стандартные → Управление расширениями
конфигурации». Флаги смотрит тот же серверный шаг по
`РасширенияКонфигурации.Получить()` (образец — `logs\smoke\ext-flags.feature`, каталог
в git не входит).

start "" "C:\Program Files\1cv8\8.5.1.1529\bin\1cv8c.exe" ENTERPRISE /F"C:\vanessa\va-manager85" /TESTMANAGER /Lru /VLru ^
  /DisableStartupDialogs /DisableStartupMessages /Out "Q:\AIZCODE.DZ8\logs\manager.log" ^
  /Execute "Q:\AIZCODE.DZ8\tools\vanessa-automation-single.epf" ^

Клиент тестирования закрылся или в базу загрузили расширение — закрыть окно клиента
и запустить его первой командой снова; менеджер не трогать.

**Запись MCP для агента** — HTTP-сервер `vanessa` с адресом `http://localhost:48100/mcp`
в MCP-конфиге своего харнесса (проектный `.mcp.json` Claude Code, `.cursor/mcp.json`,
`.codex/config.toml` и другие). Новый чат агента должен видеть инструменты `vanessa`.
В этом проекте запись уже есть в глобальном конфиге ZCode: `C:\Users\sax\.zcode\cli\config.json`,
`mcp.servers.vanessa` (`type: http`). Инструменты `vanessa` появляются в чате только при
запущенном менеджере: менеджер не запущен — чат стартует без них.

**Пакетный прогон без агента** — раннер `va.ps1` в корне проекта (адаптированный раннер
набора Vanessa урока 5): он пишет отчеты в `Q:\AIZCODE.DZ8\reports\run-<дата-время>` и сам
проверяет `status.txt` и JUnit:

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File va.ps1 -Feature features\НовыйТовар.feature -PreLaunchClient
```

Команда проверена вживую 24.11.2026: образец прошел дважды, оба раза `status.txt`=0 и
JUnit без сбоев (второй прогон — при работающем менеджере MCP). `-Feature` — файл или
каталог сценариев, `-Profile` по умолчанию `bsp32` (совпадает с профилем в сценарии),
`-User` по умолчанию `Администратор`. `-PreLaunchClient` на этой машине обязателен:
`WshShell.Run` здесь не запускает bat-файлы, и штатный запуск клиента из Vanessa падает —
раннер сам запускает тестовый клиент и Vanessa подключается к нему по TCP.

Раннер собирает `VAParams.json` прогона так: к профилю клиента (но с портами
`48050-48099`, чтобы не задеть клиента MCP) добавляются: `"КаталогФич"` — каталог или файл сценариев,
`"ВыполнитьСценарии": true`, `"ЗавершитьРаботуСистемы": true`,
`"ЗакрытьTestClientПослеЗапускаСценариев": true`, `"ДелатьОтчетВФорматеjUnit": true`
с `"КаталогВыгрузкиJUnit"`, `"ВыгружатьСтатусВыполненияСценариевВФайл": true`
с `"ПутьКФайлуДляВыгрузкиСтатусаВыполненияСценариев"` (`status.txt`). Итог прогона —
`status.txt` и JUnit, а не код процесса 1С: он 0 и при упавшем сценарии; пустой отчёт —
не успех.
